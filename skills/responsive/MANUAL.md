# Responsive & Fluid Design — الوحدة السادسة (أصلية)

> **الطبقة السائلة لكل viewport.** هذه الوحدة تجعل الواجهة تتمدّد كنظام قبل أن تُضاف إليها نقاط
> توقّف (breakpoints): التايبوغرافي والتباعد والشبكات تكون سيّالة أولًا، ونقاط التوقّف مسؤولة عن
> **التغييرات البنيوية** فقط (إعادة ترتيب أعمدة، إظهار/إخفاء أقسام). تكمل الوحدة `web-vitals`
> (التكلفة) و`a11y` (التحجيم والوصول) و`rtl-arabic` (الخصائص المنطقية داخل RTL)، وتُقرأ بعد
> `taste`/`tokens` عند البناء، وقبل `verify` عند التسليم.
>
> **العلاقة بالوحدات:** `a11y` يسود في سؤال التكبير (WCAG 1.4.4/1.4.10)، و`web-vitals` يسود في
> سؤال تكلفة الصور المتجاوبة (`srcset` بلا كسر LCP)، و`rtl-arabic` يسود في اتجاه القياسات
> (`margin-inline` بدل `margin-left`) — هذه الوحدة تملك الشبكة والسلاسة وآفة التجاوز الأفقي.

---

## §1 الفلسفة: سيّال أولًا، توقّف ثانويًا

الخطأ المؤسِّس في التصميم المتجاوب هو بناء صفحة دسكتوب ثابتة ثم «إصلاحها» بعشرين media query:
كل استعلام يصبح رقعة ترقيع متسربة، والصيانة تتضاعف مع كل شاشة جديدة. الأسلوب الصحيح معكوس:
**تُبنى الواجهة من أسفل الشاشة الأضيق (320–360px) بوحدات مرنة** — `rem` و`%` و`ch` و`dvh` —
فتتمدّد بحجم الشاشة تلقائيًا، ثم تُضاف نقاط التوقّف فقط عندما **تتغير البنية** لا المقاسات:
عمودان يصبحان ثلاثة، شريط جانبي يظهر، قائمة تنقّل تتحول من زرّurger إلى روابط أفقية.

القاعدة الحاسمة: إن احتجت media query لتغيير عرض بطاقة أو حجم عنوان، فالتصميم غير سيّال
بعد — استخدم `clamp()` أو `auto-fit` وأعد المحاولة. الصفحة السليمة تعمل بين 320px و3840px
بـ**صفر استعلامات** تقريبًا، وتحفظ الاستعلامات للبنية. ومع أي محتوى عربي تُستبدل كل الخصائص
الفيزيائية بالمنطقية (انظر rtl-arabic §1) — السلاسة والاتجاه طبقتان مستقلتان، وأحدهما لا يعالج الآخر.

**نقاط التوقّف نفسها** ليست سحرًا: استخدم مجموعة صغيرة مبنية على المحتوى الفعلي (حيث يبدأ
التصميم بالتكسّر، لا عند أرقام أجهزة معينة)، ووحداتها `em` أو `rem` لا `px` حتى تحترم إعدادات
المستخدم وتكبير الخط — مثال عملي: `48em` و`64em` و`80em` كافية في معظم المنتجات.

## §2 الإقلاع: viewport سليم أو لا شيء

السطر الأول الذي تُقرأ به أي صفحة متجاوبة هو meta viewport، وبأصحاب صيغة واحدة:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

- **غيابه كارثة**: الهاتف يفترض عرضًا 980px ويصغّر الصفحة كلها — نص غير مقروء وتخطيط ميت.
- **`user-scalable=no` أو `maximum-scale` أقل من 2 محظور** (WCAG 1.4.4): تكبير
  الشاشة حاجة فعلية لملايين المستخدمين، وتقييدها فشل إتاحة موثّق — الفاحص يعامله HIGH.
- للنماذج على iOS أضف حقلًا بـ`font-size: 1rem` على الأقل لمنع التكبير التلقائي عند التركيز.
- `viewport-fit=cover` مطلوب فقط عند استخدام safe-area insets للشاشات المفرّغة.

## §3 التايبوغرافي السائل: clamp بصيغ جاهزة

القاعدة: **الجذر (`html`) لا يقبل `px` إطلاقًا** — `html { font-size: clamp(1rem, 0.9rem + 0.25vw, 1.125rem) }`
يحافظ على تكبير المستخدم ويضيف مرونة خفيفة مع الشاشة. ثم تُبنى جميع المقاسات بـ`rem`.

للعناوين استخدم الصيغة الجاهزة (min + ميل بصري + max):

```css
h1 { font-size: clamp(2rem, 1.5rem + 2.5vw, 3.5rem); }  /* يبدأ 32px ويتوقف 56px */
p  { font-size: clamp(1rem, 0.95rem + 0.2vw, 1.125rem); }
```

قواعد مضادة للأخطاء: **لا `vw` وحدها أبدًا** (تتكبر بلا سقف على شاشات 4K وتتفكك عند zoom)،
دائمًا `clamp(min, سائل, max)`؛ ولا `clamp` على نص الفقرة الصغير إلا بمدى ضيق؛ و`line-height`
لا يقبل قيمًا مطلقة — استخدم قيمة خالية (`1.2` للعناوين، `1.6`–`1.8` للنص العربي كما نصّ
rtl-arabic §3). افحص دائمًا بحالة **zoom 200%**: إن تداخلت الكتل أو ظهر تمرير أفقي، فالمقاسات
مقفلة بمقادير مطلقة — أصلحها قبل التسليم (هذا فشل WCAG 1.4.4 لا مجرد ذوق).

## §4 وحدات القياس: لكل مقاس وحدته

| الوحدة | استعملها في | لماذا |
|---|---|---|
| `rem` | الخطوط، الهوامش، الحشوات، نقاط التوقّف | تحترم تكبير المستخدم — أساس الإتاحة |
| `%` | الأعمدة والحاويات | نسبة من الأب دائمًا |
| `ch` | عرض عمود النص | 45–75ch حزمة القراءة المريحة (أقل للعربية) |
| `min()`/`max()` | عرض حاوية: `min(100%, 72rem)` | سقف بلا media query |
| `100dvh` | أقسام full-screen | يتكيف مع شريط عنوان المتصفح المتحرك |
| `svh` | hero يجب أن يظهر كاملًا فورًا | أصغر viewport ممكن — بلا قفز |
| `vh` | ⚠️ دسكتوب فقط | على الجوال يقفز مع اختفاء شريط العنوان — CLS |
| `vw` | ⚠️ داخليًا داخل `clamp` فقط | `width: 100vw` تسبّب تمريرًا أفقيًا دائمًا (§5) |

**حظر `100vw` العرضي**: `100vw` تساوي عرض viewport **شاملة شريط التمرير العمودي**، فأي صفحة
بشريط تمرير ستحصل على تمرير أفقي مصاحب — استخدم `width: 100%` على الحاويات أو `100dvh`
للارتفاعات. هذا من أكثر الأخطاء المكتشفة في الفاحص (VW-OVERFLOW).

## §5 الشبكات السيّالة: auto-fit بلا استعلامات

أشهر نجاح للسلاسة: شبكة بطاقات تتكيف بلا أي media query:

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
  gap: clamp(1rem, 0.8rem + 0.5vw, 1.5rem);
}
```

- `auto-fit + minmax(min(100%, Nrem), 1fr)`: عدد الأعمدة يُحسب من العرض المتاح نفسه — من
  عمود واحد على الجوال إلى N على الدسكتوب **بدون استعلام واحد**، ولا يتكسر في RTL لأن
  `grid` يتبع اتجاه الكتابة تلقائيًا.
- `min(100%, 17rem)` داخل minmax يمنع التكسّر عند العروض الضيقة جدًا (بطاقة أعرض من الشاشة).
- التباعد بين العناصر بـ`gap` لا بهوامش خارجية (لا margin-collapse ولا نسخ سلبية).
- للتمرير الأفقي للشرائح استخدم `scroll-snap` مع `overflow-x: auto` بدل تكسير الشبكة.
- أعلن الحاويات بـ`max-width: min(100%, 72rem)` + `margin-inline: auto` — سقف القراءة
  المركزي بلا أي استعلام.

## §6 استعلامات الحاويات: المكوّن يتكيف بمقصورته

المكوّن القابل لإعادة الاستخدام لا يعرف أين سيوضع — لوحة جانبية أم عرض كامل. استعلامات
الحاويات تجعل **المكوّن** (لا الصفحة) مالك تجاوبه:

```css
.card-wrap { container-type: inline-size; }        /* الحاوية تنشر حجمها */
@container (min-width: 28rem) {                     /* المكوّن يستجيب لمقصورته */
  .card { display: grid; grid-template-columns: 8rem 1fr; }
}
```

قاعدة التوزيع: **الاستعلامات على الviewport للبنية الكبرى فقط** (هيدر، أعمدة الصفحة)؛
**وعلى الحاويات لكل مكوّن** (بطاقة، نموذج، وحدة وسائط). احترس من `container-type: inline-size`
داخل عنصر يعتمد ارتفاعه على محتواه — قد يخلق حلقة قياس؛ طبّقه على الغلاف مباشرة. دعم
المتصفحات مستقر منذ 2023 (Chrome/Safari/Firefox) — بديل مقبول للمشاريع القديمة فقط:
فئة معدّلة تضيفها JS عند القياس، لكن لا ترجع إلى viewport queries للمكوّنات مهما كان الثمن.

## §7 الصور والوسائط المتجاوبة

- **`aspect-ratio` يحل CLS**: ضع `width`/`height` على الوسم وأعلن `img { height: auto; }` —
  المتصفح يحجز المساحة قبل التحميل (تكمّل web-vitals §3 ولا يتعارض معها).
- **`srcset` + `sizes` للصور الكبيرة**: تخفض 60–80% من بايتات الجوال وتحسّن LCP معًا:

```html
<img src="hero-800.avif"
     srcset="hero-400.avif 400w, hero-800.avif 800w, hero-1600.avif 1600w"
     sizes="(max-width: 48em) 100vw, 60vw"
     width="1600" height="900" fetchpriority="high" alt="…">
```

- **`<picture>` للفن الاتجاهي** (قصّة مختلفة لا مجرد دقة): `<picture><source media="(max-width: 48em)" srcset="crop-square.avif">…`
- **`object-fit: cover` + `object-position`** بدل التمويه اليدوي — والقصّ الفعلي عبر
  `aspect-ratio` على الحاوية.
- **لا فيديو خلفية على الجوال**: `matchMedia('(prefers-reduced-motion)')` وعرض الشاشة يقرران
  صورة ثابتة بدلًا (تكمّل a11y §7 وweb-vitals).
- تكلفة التنزيل مسؤولية `web-vitals` — هذه الوحدة تملك **الشكل** (أبعاد محجوزة، قصّ صحيح،
  بلا تجاوز أفقي) ولا تملك الأداء.

## §8 الاختبار: نافذات معيارية وقائمة التقاط

الاختبار المعياري قبل التسليم (بترتيب ثابت — نفس ترتيب التدقيق 10 نقاط):

1. **320px** (أضيق شاشة شائعة): لا تمرير أفقي، لا نص مبتور، الأزرار قابلة للنقر.
2. **360–390px** (الشريحة الأكبر من الجوال): التباين والتباعد مقروءان.
3. **768px** (لوحي): هل انتقلت البنية أم ما زالت ترقيعًا؟
4. **1024–1440px**: السقف المركزي يعمل، الشبكة تكتمل بلا فراغات شاذة.
5. **1920–3840px**: التايبوغرافي توقف عند clamp أم انفلت؟
6. **Zoom 200% على 1280px**: مكافئ 640px — WCAG 1.4.4: المحتوى يعمل بلا تمرير ثنائي الاتجاه.
7. **RTL على كل النوافذ**: `dir="rtl"` ثم نفس العينات — الخصائص المنطقية لا تجاوبًا بلا اتجاه.

وسائل سريعة: DevTools device toolbar بأبعاد CSS حقيقية (لا تختبر بدقة منطقية فقط)،
`document.documentElement.scrollWidth > innerWidth` في الconsole يعطي إجابة التجاوز الفوري
(false = سليم)، وقياس CLS الحقيقي بعد تثبيت الأبعاد مسؤولية web-vitals §8.

## §9 سقف الرموز — اللقطات الجاهزة

```css
/* 1) إقلاع سليم */
html { font-size: clamp(1rem, 0.92rem + 0.3vw, 1.125rem); }

/* 2) حاوية مركزية بلا استعلام */
.container { width: min(100% - 2rem, 72rem); margin-inline: auto; }

/* 3) شبكة سيّالة (§5) */
.grid { display: grid; gap: clamp(1rem, 0.75rem + 0.5vw, 1.5rem);
        grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr)); }

/* 4) full-screen متكيف */
.hero { min-height: 100svh; padding-block: clamp(2rem, 1.2rem + 3vw, 5rem); }

/* 5) استعلام حاوية لمكوّن (§6) */
.card-wrap { container-type: inline-size; }
@container (min-width: 28rem) { .card { grid-template-columns: 8rem 1fr; } }
```

كل لقطة تُستخدم كما هي ثم تُربط برموز `tokens` (القيم الرقمية تصبح `--space-*` و`--step-*`
في معمارية DTCG — لا قيم خام في المكوّنات، tokens §7).

## §10 فاحص `responsive.mjs` — قواعد القياس الحتمية

`node skills/responsive/scripts/responsive.mjs page.html [dir/] [--json]` — بلا اعتماديات،
يفحص ملفات HTML (مع `<style>` وأسلوب `style="…"`) وملفات CSS مباشرة:

| # | القاعدة | الشدة | المعنى |
|---|---|---|---|
| 1 | `VIEWPORT-MISSING` | HIGH | لا meta viewport — الصفحة تفترض 980px وتنكسر |
| 2 | `VIEWPORT-LOCK` | HIGH | `user-scalable=no` أو `maximum-scale < 2` — تكبير مقفول (WCAG 1.4.4) |
| 3 | `PX-ROOT-FONT` | HIGH | `html { font-size: NNNpx }` — يكسر تكبير المستخدم والتايبوغرافي السائل |
| 4 | `FIXED-WIDTH` | MED | `width: NNNpx` (≥ 480px) — خطر تجاوز أفقي على 320–360px |
| 5 | `VW-OVERFLOW` | MED | `width/min-width: 100vw` — تمرير أفقي مع أي شريط تمرير عمودي |
| 6 | `NO-FLUID-OR-MQ` | MED | CSS بلا `clamp()/min()/max()` ولا `@media` — تصميم ثابت على الأرجح |
| 7 | `FULL-HEIGHT-VH` | LOW | `height: 100vh` — فضّل `100dvh/svh` على الجوال |
| 8 | `SRCSET-HINT` | LOW | أول صورة بلا `srcset/sizes` — بايتات وLCP مهدرة |

رمز الخروج: `0` لا HIGH · `1` يوجد HIGH (بوابة فاشلة) · `2` خطأ استخدام. الفاحص **ثابت
والبنيوي** — لا يقيس أداء حقيقي (web-vitals §8) ولا تجاوبًا حيًا (verify بمحاكاة النوافذ)،
بل يمنع الأخطاء الجارية قبل أن تصل إلى المتصفح.

## قائمة التدقيق — 10 نقاط قبل التسليم

1. meta viewport بالصيغة السليمة، بلا قفل تكبير، ويعمل عند zoom 200% بلا تمرير أفقي.
2. صفر قيم `px` على خط الجذر، وصفر `width: 100vw` في المشروع كله.
3. كل عنوان ونص فقرة على `clamp()` بمدى محدد (سقف وحد أدنى).
4. شبكات البطاقات على `auto-fit + minmax(min(100%, …), 1fr)` لا على استعلامات مضاعفة.
5. المكوّنات القابلة لإعادة الاستخدام تستجيب لـ`@container` لا للviewport.
6. كل صورة محتوى كبيرة بـ`srcset`/`sizes` + `width`/`height` + `aspect-ratio` محجوز.
7. الأقسام full-screen على `100svh/dvh` لا `100vh`.
8. تجاوز أفقي = صفر عند 320px (فحص `scrollWidth` + عين النافذة).
9. RTL سليم على كل النوافذ: خصائص منطقية، لا `left/right`، اتجاه الشبكات والتمرير صحيح.
10. الفاحص `responsive.mjs` ناتجه: صفر HIGH على كل صفحات المشروع قبل دمج أي طلب.
