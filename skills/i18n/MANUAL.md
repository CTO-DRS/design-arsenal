# i18n — التدويل العربي أولًا: واجهة تتكلم كل اللغات بلا إعادة بناء

> **وحدة أصلية في `design-arsenal` (v2.7.0)** — بنية اللغة: `lang`/`dir` الصحيحان، تنسيق الأرقام والتواريخ والعملات عبر `Intl` حصريًا، الجمع بقواعد اللغة، الخطوط العربية، والنص القابل للتوسع. التدويل قرار معماري يُتخذ أول يوم؛ إضافته بعد الشحن تعني مسح كل سلسلة مضمومة وإعادة اختبار كل شاشة. الوحدة تكمل `rtl-arabic` (التي تملك الاتجاه والتايبوغرافيا) وتتعاون مع `a11y` (القارئات تتبع `lang`) و`forms` (الحقول المحلية).
>
> **الفاحص:** `node skills/i18n/scripts/i18n.mjs <file.html|dir/> [--json]` — بلا اعتماديات، Node 18+.

---

## §1 — العقد: التدويل بنية لا ترجمة

الترجمة **محتوى** يُستبدل، والتدويل **بنية** تستقبل أي محتوى بلا إعادة بناء. الصفحة المعمّرة جيدًا تحقق أربعة شروط قبل أن تُكتب أول سلسلة فيها: لغة معلنة من أول سطر (`lang`)، واتجاه معلن (`dir`)، وصِفر تنسيق يدوي للأرقام والتواريخ والعملات (كل شيء عبر `Intl`)، ونصوص تتمدد ولا تُقص (لا عرض ثابت على ما يحمل كلامًا). إذا وُلدت السلاسل مضمومة في الشيفرة (`"إجمالي: " + total`) وبدل التاريخ يدويًا (`${y}/${m}/${d}`) فأنت لا تملك منتجًا قابلًا للتعريب — تملك منتجًا عربيًا سيُكتب من جديد ليصبح إنجليزيًا.

القاعدة الحاكمة: **كل ما يظهر للمستخدم كرقم أو تاريخ أو عملة أو قائمة أو جمع يمر عبر المنصة (`Intl`)، وكل ما يظهر ككلمة يمر عبر مورد (`messages.*`) أو DOM — لا عبر ضم سلاسل في منطق الشيفرة.** حتى لو كانت خطتك لغة عربية واحدة إلى الأبد، هذه البنية تمنع أصنافًا كاملة من الأخطاء (تنسيق يختلف بين `ar-EG` و`ar-SA`، وجمع لا يُحل بشرط `if`).

## §2 — `lang` و`dir` والنص المختلط الاتجاه

`<html lang="ar" dir="rtl">` معًا من أول سطر — هما إعلانان مختلفان: `lang` يوجه قارئات الشاشة (النطق)، والخطوط البديلة، و`Intl` الافتراضي؛ و`dir` يوجه التخطيط والخصائص المنطقية (ملكية `rtl-arabic`). إعلان أحدهما دون الآخر نصف حقيقة تُنتج نصف خلل: صفحة `lang="ar"` بلا `dir` تُقرأ صحيحًا وتُرسم معكوسة، وبالعكس تُرسم صحيحًا وتُنطق بأغرب لغة.

النص المختلط هو المصدر الأول للأخطاء الاتجاهية، وقاعدته: **كل ما يُدرج ديناميكيًا داخل نص عربي يُعزل**:

```html
<!-- الاسم المدرج من قاعدة البيانات لا يُقلب -->
<p>مراجعة <bdi>Sarah</bdi> على المنتج — قبل ساعتين</p>
<!-- المحتوى الخام المجهول الاتجاه يقرر بنفسه -->
<div dir="auto">{{user_comment}}</div>
<!-- والCSS البديل عند تعذر HTML -->
.user-name { unicode-bidi: isolate; }
```

بلا عزل، اسم مثل `Ahmad` داخل جملة عربية يُعاد ترتيبه حرفًا حرفًا (`damhA` بصريًا) وعلامات الترقيم تهرب إلى الجهة الخاطئة — خطأ لا يلتقطه اختبار يدوي سريع لأنه يظهر فقط بقيم معينة. المصطلحات التقنية المدمجة (`placeholder-كتسمية`) تُحبَّذ كتابتها معزولة أيضًا، لكن القاعدة الحاسمة هي العناصر **المدرجة وقت التشغيل**: أسماء، تعليقات، عناوين، أرقام طلبات.

## §3 — الأرقام والتواريخ والعملات عبر `Intl` حصريًا

لا استثناء واحد. التنسيق اليدوي ليس «يعمل الآن» فحسب — إنه خاطئ صراحةً في لغات أخرى، وصعب الاكتشاف لأن اختبارك يجري بلغتك:

```js
// ✗ ممنوع — يكسر كل لغة غير التي اختبرتها
const total = price.toFixed(2) + " ر.س";
const stamp = `${d.getFullYear()}/${d.getMonth() + 1}/${d.getDate()}`;
const label = count === 1 ? "عنصر واحد" : count + " عناصر";

// ✓ الصيغة الوحيدة الصحيحة
const money = new Intl.NumberFormat(locale, { style: "currency", currency: "SAR" }).format(price);
const date  = new Intl.DateTimeFormat(locale, { dateStyle: "long" }).format(d);
const ago   = new Intl.RelativeTimeFormat(locale, { numeric: "auto" }).format(-3, "minute");
const list  = new Intl.ListFormat(locale, { type: "conjunction" }).format(items);
```

انتبه لفخّ اللغة الصلبة: `toLocaleString("en-US")` في صفحة عربية يُلغي التدويل كله بصمت — مرّر لغة المستخدم (من `<html lang>` أو تفضيله المحفوظ) أو اترك الوسيط فارغًا ليرث المنصة. **نظام الترقيم قرار موحد**: `ar-EG` يعرض `١٢٣٤٥` بينما تعتمد `ar-SA` في الغالب لاتينيًا أو هجريًا بحسب المنصة — اختر سياسة واحدة (عربية هندية أو لاتينية) للمنتج كله وطبّقها عبر خيار `nu` أو بقبول الافتراضي، ولا تترك كل شاشة تقرر لحالها. العملات: `style: "currency"` يضع الرمز في جهته الصحيحة آليًا — لا تضف الرمز يدويًا أبدًا، فالضم اليدوي هو ما ينتج «٥٠ر.س» الملتصقة أو الرمز في الجهة المعكوسة.

## §4 — الجمع بـ`Intl.PluralRules`: العربية ست فئات لا اثنتان

الإنجليزية تعرف صيغتين، والعربية تعرف **ستًا** — أي شرط `if (n === 1)` هو خطأ أصلاً لا تقريب:

| العدد | الفئة | المثال |
|---|---|---|
| 0 | `zero` | لا رسائل |
| 1 | `one` | رسالة واحدة |
| 2 | `two` | رسالتان |
| 3–10 | `few` | ٣ رسائل |
| 11–99 | `many` | ١١ رسالة |
| 100+ | `other` | ١٠٠ رسالة |

```js
const pr = new Intl.PluralRules(locale);           // ← تصنّف العدد نفسه
const key = pr.select(n);                          // "zero" | "one" | "two" | "few" | "many" | "other"
const text = messages[key].replace("%n", nf.format(n));
```

وكذلك **لاحقة `(s)`** (`item(s)`, `file(s)`) ليست حلًا بل اعتراف بالهزيمة — تُقرأ بصعوبة في الإنجليزية نفسها ولا معنى لها إطلاقًا في العربية. بنية الموارد الصحيحة: مفتاح لكل فئة جمع في ملف الرسائل (`msg.cart.zero/one/two/few/many/other`)، والفاحص يكشف نصوص `(s)` المرئية تذكيرًا بذلك.

## §5 — الخطوط العربية على الويب

الخط العربي أثقل من اللاتيني (الحروف المتصلة، الأشكال السياقية)، وقواعده:

- **خط متغير واحد** بمدى وزنين (Regular↔Bold) يغلب تحميل عائلات متعددة — والخطوط العربية المتغيرة صارت معيارًا.
- **`font-display: swap`** إلزامي (وهو محظور غيابه في `web-vitals §6` أيضًا) — مع fallback عربي سليم: `font-family: "Cairo", "Segoe UI", system-ui, sans-serif` — خطوط النظام العربية (Segoe UI، SF Arabic، Noto Sans Arabic) تغطي الفترة قبل التبديل فلا يظهر نص مقطوع.
- **التقسيم (`unicode-range`/subsetting)**: لا تحمّل كل المحارف؛ خدمة مثل Google Fonts (css2) تقسم آليًا، والخط الذاتي الاستضافة يُقسم بأداة subset — يقلّ الحجم 60–80% عادةً.
- **سياسة الأرقام داخل النص**: الخط العربي الجيد يحمل محارف الأرقام العربية الهندية؛ إن اخترت أرقامًا لاتينية داخل نص عربي فتأكد أن الخط يرسمها بنفس الوزن البصري وإلا تبدو مثقوبة.
- اختبار **الوضع الداكن**: بعض الخطوط العربية الرقيقة (`weight ≤ 300`) تفقد الوضوح على السطوح الداكنة — أرضية الوزن في الداكن 400 (شراكة `dark-mode`).

## §6 — تخطيط يتكلم كل اللغات: النص القابل للتوسع

النص الألماني أطول من الإنجليزي بنسبة تصل 35%، والعربية أقصر عادةً لكن العناوين تتمدد وتلتف أكثر لأن الكلمة لا تُقطع. القواعد:

- **لا `width` ثابت بالبكسل على أي عنصر يحمل نصًا** (أزرار، شارات، وسوم، تسميات) — `padding` + `min-width` يكفيان، والنص يحدد العرض.
- **لا نص داخل صور** أبدًا — لا يُترجم ولا يُكبَّر ولا يُقلب؛ الشعار النصي ملف SVG بـ`<text>` أو HTML.
- القصّ الآمن: `overflow: hidden; display: -webkit-box; -webkit-line-clamp: 2` مع `title` كامل، لا قصًّا بحروف مخفية.
- `text-wrap: balance` للعناوين القصيرة و`text-wrap: pretty` للفقرات — العربية تستفيد منهما خاصةً في العمود الضيق.
- الأيقونة والنص بفجوة `gap` لا بمواضع مطلقة — لأن ترتيبهما ينقلب مع الاتجاه (ملكية `rtl-arabic §1`).
- تختبر الشاشة الحرجة بأطول لغة في خطتك، لا بلغتك: إن كانت الواجهة ستنطلق `ar`/`en`/`de` فشاشة الدفع تُختبر بالألمانية عند 320px.

## §7 — المدخلات المحلية: لوحة مفاتيح المستخدم وعنوانه

`forms` تملك عقد النموذج العام (تسمية، `autocomplete`، تحقق)؛ هنا ما يخص اللغة:

- **`type` للدلالة و`inputmode` للوحة المفاتيح**: `type="tel" inputmode="tel"` للجوال، `inputmode="numeric"` لرمز OTP (مع `dir="ltr"` — ملكية `forms`)، `inputmode="decimal"` للأسعار.
- **اقبل الأرقام العربية الهندية** (`٠١٢٣`) في حقول الأرقام والهاتف: المستخدم يكتب بما تراه لوحته — حوّل عند المعالجة، ولا تعاقب من يكتب `٠٥٥` بدل `055`.
- **العناوين مفككة**: `address-line1/2` + `city` + `postal-code` كحقول مستقلة بأسماء `autocomplete` معيارية — حقل «العنوان» النصي الحر الواحد يفشل في كل دولة ما عدا دولتك.
- **الجوال بصيغته الدولية**: `+9665XXXXXXXX` مع تلميح بصري للبادئة، والتحقق بتعبير متسامح يقبل `+` ومسافات وأرقامًا هندية.
- لا تُلزم «الاسم الأول/الأخير» بالحرفية: كثير من الأسماء العربية لا تنقسم كذلك — `name` كامل مع حقل اختياري أفضل من فصل يرفض أسماء حقيقية.

## §8 — المحتوى الثقافي: ما لا يحلّه `Intl`

المنصة تنسّق الأرقام؛ لكنها لا تقرر **أي تقويم يعيش فيه منتجك** ولا **كيف تُخاطب الناس**:

- **التقويم**: `Intl.DateTimeFormat(locale, { calendar: "islamic-umalqura" })` يدعم الهجري — القرار (ميلادي وحده، هجري وحده، انتقاء المستخدم) قرار منتج يُوثَّق ويُطبَّق موحدًا، وواجهة الانتقاء خيار ملف تعريف لا قائمة منسدلة في زاوية.
- **بداية الأسبوع**: السبت في معظم العالم العربي والأحد في أمريكا — مكوّن التقويم الجاهز يُضبط `firstDay` صراحةً، وإلا كان الأسبوع يبدأ بوجهين مختلفين في شاشتين مختلفتين.
- **صيغة الوقت**: `hour12` قرار منطقة (`ar-SA` بنظام 12، `ar-EG` متغير) — مرره من تفضيل المستخدم لا من ثابت.
- **النداء**: «أنت/حضرتك» قرار تحريري موحد له مالك — لا يتغير بين الشاشات.
- **الرموز**: علم الدولة بإيموجي يختفي على بعض الأنظمة — أيقونة أو رمز نصي `SA`. والألوان الرمزية (الذهبي/الأحمر) تختلف دلالتها ثقافيًا — وثّق معانيها في ملف الرموز، لا في عقول المصممين.

## §9 — سقف الرموز: الرسائل بيانات لا سلاسل مضمومة

الترجمة تحتاج قائمة سلاسل؛ والتدويل يحتاج أن تكون تلك القائمة **مصدرًا واحدًا**:

- كل نص واجهة **مفتاح** في ملف موارد (`messages.ar.json`) لا سلسلة مضمومة في شيفرة المكوّن — حتى بلا إطار i18n: مجلد `locales/` و`import` واحد يكفيان.
- ما لا يدخل الموارد أبدًا: أسماء العلامات، الشيفرة، مسارات URLs. ما لا يخرج منها أبدًا: زر «إرسال».
- التضمين داخل المنطق (`if (lang === "ar") return "مرحباً"`) هو الشكل الأخطر — يتضاعف مع كل لغة حتى تنفجر الشيفرة. البديل: دالة `t(key)` واحدة وست فئات الجمع من §4.
- التاريخ والتاريخ الهجري والعملة كلها **قرارات إعداد** في ملف واحد (`i18n.config`): `locale`، `calendar`، `currency`، `hour12` — لا ثوابت مبثوثة.

**الفاحص** (`i18n.mjs`) يصطاد البنية المكسورة قبل أن تُشحن — قواعده التسع:

| القاعدة | الخطورة | ما تلتقطه |
|---|---|---|
| `LANG-MISSING` | HIGH | `<html>` بلا `lang` — القارئات تُنطق باللغة الخاطئة |
| `ARABIC-NO-DIR` | HIGH | محتوى عربي و`<html>` بلا `dir` — النصف المرسوم مكسور |
| `MANUAL-DATE` | MED | تاريخ يُبنى يدويًا (`${y}/${m}/${d}`) بدل `Intl.DateTimeFormat` |
| `LOCALE-HARDCODED` | MED | لغة `'en'` صلبة داخل `Intl`/`toLocaleString` تُبطل لغة المستخدم |
| `TOFIXED-MONEY` | MED | `.toFixed(2)` على قيمة مالية بدل `Intl` بصيغة عملة |
| `PLURAL-GENERIC` | MED | نص `(s)` — صيغة جمع واحدة للغات كلها |
| `FIXED-WIDTH-TEXT` | MED | `style="width:Npx"` على زر/رابط يحمل نصًا — القص مضمون بلغة أطول |
| `FIXED-WIDTH-CSS-HINT` | LOW | قاعدة CSS بعرض px ثابت على محدد زر/شارة/وسم (تحقق: هل يحمل نصًا؟) |
| `FONT-NOSUBSET` | LOW | `@font-face` بلا `unicode-range` — تحميل خط كامل ثقيل |

## §10 — مصفوفة الاختبار قبل التسليم

| الفحص | ما يُقاس | النجاح |
|---|---|---|
| قلب اللغة كاملًا | `ar ↔ en` عبر كل الشاشات | لا نص مقصوص ولا سلسلة تائهة |
| أطول لغة | شاشة الدفع بالألمانية عند 320px | صفر تجاوز أفقي |
| التواريخ والعملات | `ar-EG` و`ar-SA` و`en` جنبًا إلى جنب | صيغ صحيحة ونظام ترقيم موحد |
| الجمع | `0 / 1 / 2 / 3 / 11 / 100` | ست صيغ صحيحة لا صيغة وحيدة |
| الاسم المدرج | اسم `Latin` داخل جملة عربية والعكس | معزول بـ`<bdi>` لا يُقلب |
| قارئ الشاشة | NVDA/VoiceOver **بالعربية** | النطق عربي والاتجاه صحيح |
| لوحة المفاتيح | كل مسار بالـTab | التركيز يتبع الترتيب المنطقي بعد القلب |
| لوحة الأرقام | كتابة `٠٥٥` في الجوال وOTP | مقبولة ومحوّلة صحيحة |
| الوضع الداكن | الخط العربي بوزن 400 | لا نص باهت أو مكسور |
| الفاحص | `i18n.mjs` على كل الصفحات | صفر HIGH |

## تدقيق 10 نقاط قبل التسليم

1. `lang` و`dir` على `<html>` معًا من أول سطر — وأي عنصر بلسان مختلف يحمل `lang` خاصًا به.
2. صفر تنسيق يدوي: كل رقم وتاريخ وعملة عبر `Intl` — الفاحص لا يرى `toFixed` ماليًا ولا قالب `${y}/${m}/${d}`.
3. الجمع عبر `Intl.PluralRules` بست فئات عربية — لا شرط `n === 1` ولا لاحقة `(s)` في أي نص.
4. كل قيمة مدرجة ديناميكيًا داخل نص معكوس معزولة (`<bdi>` أو `dir="auto"` أو `unicode-bidi: isolate`).
5. لا عرض بكسل ثابت على ما يحمل نصًا — الأزرار والشارات تتمدد بـ`padding`/`min-width`.
6. لا نص داخل صور — والشعار النصي SVG بـ`<text>` أو HTML قابل للترجمة.
7. الخط العربي: `font-display: swap` + تقسيم `unicode-range` + fallback نظام سليم + وزن ≥ 400 في الداكن.
8. الحقول: `type`/`inputmode`/`autocomplete` صحيحة، العناوين مفككة، والأرقام الهندية مقبولة ومحوّلة.
9. الرسائل مفاتيح في ملف موارد واحد — وإعدادات اللغة/التقويم/العملة إعداد مركزي لا ثوابت مبثوثة.
10. مصفوفة الاختبار §10 كاملة مرتين: بالعربية وبالثانية المخطط لها — قبل أن تُعلن «جاهز للتدويل».
